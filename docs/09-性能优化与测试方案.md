# 第九部分：性能优化与测试方案

## 1. 当前性能设计（已生效）

| 项 | 现状 | 说明 |
|---|---|---|
| 页面形态 | 纯静态 HTML + CDN | 无数据库、无服务端渲染延迟 |
| 图片 | Hugo 自动生成 800/1600/2400 多档尺寸 + `srcset` + 懒加载 | 主题 `imageProcessing` 已开启；PhotoSwipe 点击放大按需加载 |
| 字体 | 系统字体栈 | 0 KB 字体下载 |
| CSS/JS | 构建时压缩、带内容哈希文件名 | `hugo --minify` |
| 第三方脚本 | 默认 0 个 | 统计/评论启用后才引入，且评论懒加载 |
| 公式/图表 | KaTeX/Mermaid 仅文章包含时才加载 | 不用不付出 |

## 2. 图片规范（写作时执行）

1. **格式**：照片用 JPG（质量 80~85）、扁平图形用 PNG、图标优先 SVG；
2. **尺寸**：原图长边 ≤ 2400px（再大也被主题缩到 2400）；
3. **压缩**：上传前过一遍 <https://squoosh.app>（Google 开源，可选 WebP/AVIF 导出）；
4. **AVIF/WebP**：面向现代浏览器收益明显。可选进阶：在 Hugo 里对资源调用 `.Process "resize 1600x webp"`；当前主题默认 JPG 已足够好，**不必为指标焦虑**；
5. 每图必有 ALT（同时是 SEO 与 a11y 要求）。

## 3. 缓存与网络

- 静态资源长缓存（文件名带哈希，放心缓存一年）；
- HTML 短缓存：文章更新分钟级可见；
- 平台自带 CDN，无需自建；国内访问速度受限于未备案，属物理现实（见 13 的国内方案）。

## 4. Core Web Vitals 目标与检测

指标基线（Google 标准）：**LCP < 2.5s · CLS < 0.1 · INP < 200ms**。

### 检测流程（优化前后各跑一遍对比）

1. **PageSpeed Insights** <https://pagespeed.web.dev>
   - 输入首页与**最长的一篇文章**的 URL；
   - 分别记录移动端/桌面端的 LCP、CLS、INP 与建议项；
   - 新站无真实用户数据时看“实验室数据”即可。
2. **Lighthouse**：Chrome 打开站点 → F12 → Lighthouse 面板 → 移动端档位跑一次（结果与 PSI 同源）。
3. **WebPageTest** <https://www.webpagetest.org>：需要看瀑布图定位慢资源时用。

预期：本站点移动端分数 90+（静态 + 无字体 + 懒加载）。若低于 80，优先查：超大未压缩图片、额外引入的第三方脚本。

## 5. 第三方脚本纪律

| 规则 | 原因 |
|---|---|
| 每加一个脚本前问：价值 > 加载成本？ | 防堆砌 |
| 一律 `defer` 或懒加载 | 不阻塞首屏 |
| 不引入广告、弹窗、强制关注公众号类组件 | 阅读体验红线 |
| 评论组件 `loading="lazy"`（giscus 已配置） | 评论区在首屏之外 |

## 6. 移动端真机验证清单

- [ ] 手机 4G/5G 环境打开首页与文章页，3 秒内可读；
- [ ] 导航菜单可点开收起，按钮不小于 44×44px 触控区；
- [ ] 图片点击可放大，双指缩放正常；
- [ ] 代码块横向滚动不破坏页面布局；
- [ ] 深色模式切换无闪白。
