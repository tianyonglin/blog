# 第五部分：从零部署教程

> 两条路线二选一。**路线 A（GitHub Pages）**零额外账号，推荐首选；
> **路线 B（Cloudflare Pages）**后续扩展性更强。两者不可混配步骤。

## 前置准备（两条路线通用）

| 需要 | 说明 |
|---|---|
| GitHub 账号 | 到 <https://github.com/signup> 注册（需邮箱验证），**立即开启两步验证**（头像 → Settings → Password and authentication） |
| Git | Windows 装 <https://git-scm.com/download/win>；macOS 终端执行 `xcode-select --install` |
| 域名 | 你的 `.top` 已购，下文以 `sunmusic.top` 为例 |
| 本仓库代码 | 即 `blog/` 目录 |

---

## 路线 A：GitHub Pages（推荐）

### A1. 创建仓库并推送代码

执行环境：本机终端（Windows 用 Git Bash / PowerShell 均可，macOS 用终端）。
执行目录：`blog/` 的上一级目录。

```bash
cd blog
git init
git add -A
git commit -m "init: 博客初版"
```

在 <https://github.com/new> 新建空仓库（名字随意，如 `blog`；**不要**勾选添加 README），然后：

```bash
git branch -M main
git remote add origin https://github.com/tianyonglin/blog.git   # ⚠️ 换成你的
git push -u origin main
```

预期结果：仓库里能看到全部源码。

### A2. 开启 Pages 并走 Actions 构建

1. 仓库页 → **Settings → Pages**；
2. **Build and deployment → Source** 选 **GitHub Actions**（注意：不要选 "Deploy from a branch"）；
3. 推送代码后，仓库 **Actions** 标签页可以看到 `Deploy Hugo site to Pages` 运行；
4. 绿勾后，**Settings → Pages** 顶部显示站点地址（先是 `https://tianyonglin.github.io/blog/`）。

> 本仓库的 `.github/workflows/hugo.yml` 已锁定 Hugo v0.167.0，构建命令 `hugo --minify`，产物目录 `public/`，无需修改。

### A3. 绑定自定义域名

1. 先把 `config/_default/hugo.toml` 的 `baseURL` 改成 `https://sunmusic.top/`，提交推送；
2. 到域名注册商的 DNS 管理处添加记录（详细解释见文档 06）：

   | 类型 | 主机记录 | 记录值 |
   |---|---|---|
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |
   | CNAME | www | tianyonglin.github.io |

   （IP 为 GitHub 官方公布的 Pages 地址：<https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site>）
3. 回到仓库 **Settings → Pages → Custom domain** 填 `sunmusic.top` → Save；
4. 等 DNS 生效（几分钟~几小时）后，勾选 **Enforce HTTPS**（灰色表示证书还在签发，稍等再试）。

预期结果：`https://sunmusic.top` 与 `https://sunmusic.top` 均可访问。

### A4. 日常发布流程

```bash
# 写好后
git add -A && git commit -m "post: 新文章标题" && git push
```
或者**完全不装 Git**：在 GitHub 网页上 `content/post/` 里直接新建文件夹和 `index.md`，网页提交即触发发布。

## 路线 B：Cloudflare Pages

> 官方文档：<https://developers.cloudflare.com/pages/framework-guides/deploy-a-hugo-site/>

### B1. 推送代码
同路线 A 的 A1（仓库不必公开）。

### B2.（推荐）把域名 DNS 托管到 Cloudflare

1. 注册 <https://dash.cloudflare.com/sign-up>；
2. 左侧 **Websites → Add a site** 输入你的域名，选 Free 计划；
3. Cloudflare 给出两个名称服务器（如 `xxx.ns.cloudflare.com`）；
4. 到域名注册商处把 **Nameservers 改为这两个值**（注意：是改 NS，不是加 A 记录）；
5. 等待生效（通常几分钟到 24 小时），Cloudflare 面板显示 Active。

### B3. 创建 Pages 项目

1. Cloudflare 面板 → **Workers & Pages → Create → Pages → Connect to Git**，授权并选择你的仓库；
2. **Build settings**：Framework preset 选 **Hugo**，确认：
   - Production branch：`main`
   - Build command：`hugo -b $CF_PAGES_URL`
   - Build output directory：`public`
3. **Settings → Environment variables** 添加 `HUGO_VERSION` = `0.167.0`（锁定版本，避免平台默认版本漂移）；
4. Save and Deploy。完成后获得 `https://项目名.pages.dev` 预览地址。

### B4. 绑定自定义域名

项目页 → **Custom domains → Set up a custom domain** → 输入 `sunmusic.top`。
因 DNS 已托管在 Cloudflare，记录与证书**全自动**配置，无需手工加 A/CNAME。
如还需裸域 `sunmusic.top`，再添加一条并选择重定向到 `www`（或使用 CNAME flattening，Cloudflare 自动支持根域 CNAME）。

预期结果：两个域名均带有效证书。

### B5. 与路线 A 的差异提醒

- 路线 B **不需要**仓库里的 Actions 工作流（保留也无妨，二选一即可，避免混淆可删除 `.github/`）；
- 路线 B 不在 GitHub Settings → Pages 里做任何操作。
