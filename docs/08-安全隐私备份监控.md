# 第八部分：安全、隐私、监控、备份与恢复

## 1. 威胁模型（静态博客版）

没有服务器和数据库，攻击面只剩四个：**账号**、**供应链（依赖/主题）**、**第三方服务**、**内容误操作**。方案围绕这四点设计。

## 2. 账号与访问保护（必备）

| 账号 | 措施 |
|---|---|
| GitHub | ① Settings → Password and authentication 开启 **2FA/Passkey**（必备）；② 用细粒度 Personal Access Token 或 SSH 密钥，不用密码推代码；③ 定期检查 Settings → Sessions 与 Authorized tokens |
| 域名注册商 | 开 2FA、开域名锁、关闭“免确认转移” |
| Cloudflare（若用） | 开 2FA；免费档可开 **登录挑战** |
| 密码管理 | 所有账号用密码管理器（如 Bitwarden 免费档）生成并保存强密码，**不重复使用** |

> 本方案**没有管理后台**，因此“后台爆破/弱口令”风险不存在；评论走 GitHub 登录，垃圾评论由 GitHub 风控兜底。

## 3. 密钥与敏感信息（必备纪律）

- 仓库是公开的（建议公开以展示源码），**任何 API key / token / 邮箱密码都不进代码**；
- 统计、评论等只需公开 ID（如 GA 的 `G-XXX`、Umami 的 website-id），不存在需要保密的配置；
- 万一误提交密钥：立即到对应平台**作废并重置**，再用 `git filter-repo` 清历史（预防 > 补救）。

## 4. 依赖与供应链（推荐节奏）

| 项 | 节奏 | 操作 |
|---|---|---|
| Hugo 版本 | 每季度或需要新特性时 | 升 `hugo.yml` 的 `HUGO_VERSION`，本地或预览部署验证后再合并 |
| Stack 主题 | 半年一次或有安全公告时 | 下载新版替换 `themes/hugo-theme-stack/`，本地 `hugo` 构建 + 目测首页/文章页 |
| GitHub Actions | 依赖极少 | 可用 Dependabot：仓库 Settings → Security → Dependabot alerts 打开 |
| 第三方脚本（统计/评论） | 启用前评估 | 只选知名服务；脚本保持 `defer`；不引用来路不明的“小工具” |

## 5. 备份与恢复（必备）

**第一备份 = Git 仓库本身**（全文 + 配置 + 图片）。再加两道保险：

### 5.1 本地离线备份（每季度）

执行环境：任意装有 git 的终端；预期结果：得到一个单文件备份包。

```bash
git clone --mirror https://github.com/tianyonglin/blog.git blog-mirror.git
# 或已有仓库时：
cd blog && git fetch --all && cd .. && tar czf blog-backup-$(date +%F).tar.gz blog-mirror.git
```

把 `.tar.gz` 存到网盘/移动硬盘（至少两处）。`--mirror` 包含全部分支与历史。

### 5.2 平台侧备份（自动）

- GitHub 仓库可导出：仓库 Settings → Transfer/Export（Danger zone 区域有 export）；
- Cloudflare Pages 不需要备份（它只是托管构建产物）。

### 5.3 恢复演练（每年至少一次）

```bash
# 模拟灾难恢复：从备份包重建工作副本
tar xzf blog-backup-2026-10-12.tar.gz
git clone blog-mirror.git blog-restored
cd blog-restored && hugo          # 本地构建验证
# 确认无误后可将其指向新的远端仓库恢复发布
```

预期结果：能在 30 分钟内完整重建站点。**不演练的备份等于没有备份。**

## 6. 监控与可用性（推荐）

| 项 | 工具 | 说明 |
|---|---|---|
| 可用性监测 | UptimeRobot 免费档 <https://uptimerobot.com> | 添加首页与任意一篇文章的 URL，每 5 分钟探测，宕机邮件提醒 |
| 证书到期 | UptimeRobot 附带 / Cloudflare 面板 | 平台自动续期，仅兜底 |
| 抓取与死链 | GSC「网页索引」报告 + 文档 11 的死链检查 | 每周看一次邮件摘要即可 |
| 流量统计 | 启用统计后看趋势 | 不追求精确，关注量级变化 |

静态站无应用日志可查，异常通常只有两类：构建失败（看 CI 日志）与平台故障（看 <https://www.githubstatus.com> / <https://www.cloudflarestatus.com>）。

## 7. 隐私合规（必备）

已在 `/privacy/` 页面落实，启用服务时同步更新该页：

1. **启用统计**：披露服务名、收集内容、匿名化方式；Umami/GA4 均不强制 Cookie 弹窗，但欧盟访客较多时考虑 Cookie 同意（主题内置 `cookies.enabled` 开关）；
2. **启用评论**：披露评论系统及其处理的数据（giscus 依赖 GitHub，评论者需有 GitHub 账号）；
3. **不使用**：广告网络、追踪型分享按钮（本方案的分享按钮为纯链接，不加载第三方脚本）；
4. 文章引用他人图片/内容注明来源；
5. 联系邮箱建议使用专用邮箱（如域名邮箱或独立邮箱），减少主邮箱暴露。
