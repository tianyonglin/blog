# 第十部分：文章模板、代码块样式与技术文章规范

## 1. 标准文章模板（仓库 `archetypes/default.md`）

新建文章（执行环境：装有 Hugo 的本机；或直接网页复制文件夹）：

```bash
hugo new post/my-post/index.md    # 在 blog/ 目录执行
```

Front matter 规范（`content/post/<slug>/index.md` 顶部）：

```yaml
---
title: "标题：结论或主题前置，≤30 字"
date: 2026-10-12            # 发布日期
lastmod: 2026-10-12         # 实质性修改后更新（显示“更新于”并更新 JSON-LD）
slug: my-post               # URL：小写英文短横线，发布后不再改
image: cover.jpg            # 封面：文章文件夹内放 cover.jpg
categories: ["技术"]         # 分类：只能一个（技术/生活/阅读，新增见分类目录）
tags: ["Hugo", "教程"]       # 标签：2~5 个
description: "60~120 字摘要：这篇解决什么问题、读者能得到什么"
draft: false
---

开头两段：背景 + 这篇文章讲什么 + 适合谁读。

<!--more-->

正文……（more 标记上方内容会出现在列表页摘要里）
```

## 2. 目录与配图

```
content/post/my-post/
├── index.md
├── cover.jpg        # 封面（首页卡片/分享预览/JSON-LD 都用它）
└── fig-1.png        # 插图：![](fig-1.png)，说明文字写在 alt 里
```

- 图片写图注：`![图 1：构建流程示意](fig-1.png)`；
- 截图保留关键区域即可，宽度不超过 1600px。

## 3. 代码块规范

| 规则 | 示例 |
|---|---|
| 必须标注语言（决定高亮） | ` ```bash `、` ```python `、` ```yaml `、` ```text ` |
| 终端命令与输出分开 | 命令用 `bash`，纯输出用 `text` |
| 命令注明执行环境与目录 | 正文写明“在 `blog/` 目录、bash 下执行” |
| 文件内容块写明路径 | 代码块前一行写：`文件：config/_default/hugo.toml` |
| 展示预期结果 | 命令后写“预期结果：……” |

命令 + 输出示例：

````markdown
```bash
cd blog && hugo server   # 本地预览
```

```text
预期输出：
Web Server is available at http://localhost:1313/
```
````

主题自带代码高亮（行号）与一键复制按钮，无需配置。

## 4. 技术文章结构规范（建议骨架）

1. **背景与问题**：遇到什么、为什么值得写；
2. **环境与版本**：软件/依赖版本、操作系统 —— 技术文章**必须**写清复现环境；
3. **方案与步骤**：编号步骤 + 命令 + 预期结果；
4. **踩坑记录**：报错原文 + 原因 + 解决；
5. **验证方式**：读者如何确认自己成功了；
6. **参考链接**：官方文档（用真实链接，发布前点开确认能打开）。

## 5. 表达组件速查

| 需求 | 写法 |
|---|---|
| 提示/警告框 | `> [!TIP]` / `> [!WARNING]`（GitHub 风格 Alerts） |
| 折叠内容 | `<details><summary>标题</summary>内容</details>` |
| 流程图 | ` ```mermaid ` 代码块 |
| 公式 | 行内 `$E=mc^2$`，块级 `$$…$$` |
| 表格 | 标准 Markdown 表格 |
| 键盘按键 | `<kbd>Ctrl</kbd> + <kbd>C</kbd>` |
| 系列文章 | 在 front matter 加 `series: ["名称"]`，文末手动放同系列链接 |

## 6. 发布前质检清单（每篇过一遍）

- [ ] 标题、description、slug、分类、标签齐全
- [ ] 封面图存在且有 ALT
- [ ] 代码块都标了语言，命令可在干净环境复现
- [ ] 外链全部能打开，官方文档为最新版页面
- [ ] 无错别字（尤其专有名词）
- [ ] 本地 `hugo` 构建无警告，或直接在 GitHub 预览部署中点开
- [ ] 与旧文做了互链（至少一处）
