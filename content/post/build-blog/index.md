前阵子注册了一个心仪的 `.top` 域名，接下来要做的，就是把它变成一个真正能访问的网站。这里把整个过程记录下来，方便日后的自己，也方便同样想建站的朋友。

<!--more-->

## 一、先选方案

搭博客大致有三条路：

1. **内容平台**（知乎、简书、公众号）：零门槛，但数据不完全属于自己，域名也不是自己的；
2. **WordPress 等传统 CMS**：功能强大，但要买服务器、维护数据库、操心安全；
3. **静态网站**：用 Markdown 写文章，生成器编译成 HTML，丢到免费的静态托管上。

我的需求很简单：以文字和图片为主，不用数据库。于是选了第三条路：**Hugo 生成器 + Stack 卡片式主题 + GitHub Pages 免费托管**，写文章只需要新建一个 Markdown 文件。

## 二、技术栈一览

| 环节 | 选择 | 说明 |
| --- | --- | --- |
| 生成器 | Hugo | 速度极快，一个可执行文件搞定 |
| 主题 | Stack | 卡片式设计，自带搜索、目录、评论接口 |
| 托管 | GitHub Pages | 免费，配合 GitHub Actions 自动构建 |
| 域名 | `.top` | 解析到托管平台，自动签发 HTTPS 证书 |

## 三、关键步骤

1. 把博客源码（`content/` 里的 Markdown 和配置）推到 GitHub 仓库；
2. 仓库里放一个 GitHub Actions 工作流，每次推送自动执行 `hugo` 构建并发布到 Pages；
3. 在仓库 Settings → Pages 里确认 Source 为 **GitHub Actions**；
4. 在 Pages 设置中绑定自定义域名，然后到域名注册商处添加解析记录：

```text
A      @        185.199.108.153
A      @        185.199.109.153
A      @        185.199.110.153
A      @        185.199.111.153
CNAME  www      tianyonglin.github.io
```

等几分钟到几小时，解析生效后就能用自己的域名访问了，HTTPS 证书会自动签发。

## 四、踩过的坑

- DNS 修改后要过几分钟到几小时才生效，改完打不开先别慌，等一等再试；
- `www` 和裸域名（`@`）是两条不同的记录，容易漏配其中一条；
- 如果用 Cloudflare 做解析再指向 GitHub Pages，记得把代理那朵「云」先切成 `DNS Only`，否则可能遇到证书报错。

## 五、后续计划

- 接入评论系统（基于 GitHub Discussions 的 giscus，免费且无广告）；
- 加一个轻量的访问统计（Umami 或 Cloudflare Web Analytics）；
- 慢慢填充内容 —— 博客上线只是开始，写才是正事。

如果你也想拥有一个自己的博客，动手吧 —— 它比想象中便宜，也比想象中简单。
